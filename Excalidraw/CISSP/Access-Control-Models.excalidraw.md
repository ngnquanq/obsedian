Access Control Models — Comparison ^title

DAC — Discretionary Access Control ^ZXyYDWjb

Who decides: Resource OWNER
Mechanism: Owner sets ACL on object
Example: Windows NTFS, Linux chmod
Flaw: Owners can grant excessive access

Owner transfers discretion -> privilege drift ^STNcLejt

MAC — Mandatory Access Control ^vLKQP9eS

Who decides: SYSTEM enforces (users cannot override)
Mechanism: Labels on subjects AND objects
Bell-LaPadula: No read up / No write down
Biba (integrity): No write up / No read down

Example: SELinux, classified government systems ^nlMDiGu1

RBAC — Role-Based Access Control ^3I9egjJM

Who decides: ADMINISTRATOR assigns roles
Mechanism: User -> Role -> Permissions
Example: AD groups, SailPoint IIQ
Benefit: Change role = change access instantly

Non-discretionary: owner cannot override ^WCDKY2Fv

Rule-Based Access Control ^vfYzRTQ1

Who decides: GLOBAL RULES (apply to all subjects)
Mechanism: IF conditions THEN allow / deny
Example: Firewall ACLs, router access lists
Key: Rules are NOT user-role-specific

Distinct from RBAC -- no concept of user roles ^9GxYCFuF

ABAC — Attribute-Based Access Control ^vTQFwLYH

Who decides: POLICY ENGINE
Mechanism: Subject + Resource + Environment attrs
Standard: XACML policy language
Example: AWS IAM policies, SDN controllers

Most flexible -- fine-grained, contextual decisions ^OoEriiJZ

Risk-Based (Adaptive) Access Control ^gj5ZmlkZ

Who decides: RISK ENGINE (real-time scoring)
Mechanism: Context -> risk score -> decision
Example: Azure Conditional Access, Okta
Triggers: Location, device state, behaviour

MFA step-up when risk score is elevated ^0LoRL8iJ

PDP / PEP Architecture (applies to ALL models above)

PDP = Policy Decision Point: evaluates the policy and makes the allow/deny decision (e.g. XACML engine, KDC, firewall CPU)
PEP = Policy Enforcement Point: intercepts the request and enforces the PDP decision (e.g. file server, API gateway, NIC on a switch) ^46yfFDjc

Exam: MAC = system enforces (no user override)  |  DAC = owner decides  |  Rule-Based != RBAC (no roles)
Implicit deny applies to all models  |  ABAC is most flexible  |  Constrained interface = menu limits what user can request ^PK1vVc2E
