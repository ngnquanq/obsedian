# Semi-Supervised Evaluation

Semi-supervised learning can look better during training simply because the model trained on its own guesses. Evaluation must separate true labels from generated labels.

---

## Evaluation Design

Use this minimum setup:

| Component | Purpose |
|---|---|
| Labeled-only baseline | Shows what unlabeled data adds. |
| Clean labeled validation set | Tunes thresholds and method choices. |
| Clean labeled test set | Measures final performance. |
| Pseudo-label audit | Checks confidence, class balance, and error patterns. |

The test set must contain human-confirmed or otherwise reliable labels, not pseudo-labels.

---

## What to Compare

Compare:

- labeled-only model;
- semi-supervised model;
- semi-supervised model by label-scarce segments;
- performance as pseudo-label confidence thresholds change;
- class distribution before and after adding pseudo-labels.

> [!warning] Common mistake
> Do not evaluate a semi-supervised model on examples whose labels were generated by the same model family. That measures agreement with itself, not correctness.

---

## Failure Modes

| Failure Mode | Symptom |
|---|---|
| Confirmation bias | Early wrong labels become stronger after retraining. |
| Distribution mismatch | Unlabeled data helps validation but fails in production. |
| Class collapse | Pseudo-labels overrepresent majority classes. |
| Leakage | Unlabeled features include future or post-decision information. |
| False confidence | More training data reduces uncertainty without improving correctness. |
